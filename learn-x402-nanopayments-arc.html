x402 nanopayments on Arc for AI agents

An AI agent that pays per API call needs three things from its settlement layer: predictable cost, instant finality, and no volatile token to hold. Arc is the first L1 where all three are true at once, which is why the agentic economy is where the ecosystem programme is concentrating its funding.

The flow

1. Agent  -> GET /premium-endpoint
2. Server -> 402 Payment Required  + price quote
3. Agent  -> settle sub-cent USDC on Arc
4. Agent  -> GET /premium-endpoint  with proof of payment
5. Server -> 200 + payload

That is the whole protocol. The interesting part is what happens at step 3.

Why this only works on Arc

Requirement Why most chains fail it
Fee must be predictable Volatile native gas token — an agent cannot budget against it
Fee must be smaller than the payment A $0.0004 API call cannot carry a $0.30 fee
Settlement must be instant Probabilistic finality means retries, timeouts, ambiguity
No second token to hold Agents holding ETH to pay gas is an operational nightmare

Arc answers all four: USDC-denominated fees with EWMA-smoothed EIP-1559 pricing (design target ~$0.001 per transfer), sub-second deterministic finality, and no separate gas asset.

The client

interface PaymentQuote {
  amount: string;    // "0.0004" — fractions of a cent
  payTo: string;
  scheme: string;
  network: string;
  nonce: string;
}

async function paidFetch(
  url: string,
  settle: (q: PaymentQuote) => Promise<{ proof: string }>,
  maxSpendPerCall = "0.01",
): Promise<Response> {
  let res = await fetch(url);

  if (res.status === 402) {
    const quote: PaymentQuote = await res.clone().json();

    // Hard ceiling. An agent in a retry loop with no cap is a drained wallet.
    if (Number(quote.amount) > Number(maxSpendPerCall)) {
      throw new Error(`Refusing ${quote.amount} USDC: over per-call ceiling`);
    }

    const { proof } = await settle(quote);
    res = await fetch(url, { headers: { "X-PAYMENT": proof } });
  }

  return res;
}

The server side, using Circle Nanopayments, is in the official sample: https://github.com/circlefin/arc-nanopayments

Guardrails you must ship if real money is involved

This is the part that separates a demo from a product, and it is where clients pay for help.

  1. A per-call ceiling AND a per-hour budget. Both, not either. A ceiling without a budget still allows 10,000 calls.
  2. Idempotency. Reuse the nonce so a retry cannot double-pay. Agents retry on timeout by nature.
  3. Persist every settlement with the task id. Agents restart; the ledger is the only memory that survives a crash.
  4. Give the agent an identity. ERC-8004 provides an onchain registry for agent identity, reputation events and credential verification, so a counterparty has something to price risk against. https://docs.arc.io/arc/tutorials/register-your-first-ai-agent
  5. Keep spending policy outside the agent. Circle Agent Stack provides policy-controlled agent wallets. If the agent can rewrite its own limits, it has no limits.

The commercial angle

The obvious product is "sell API access to agents." The less obvious and more valuable one is the infrastructure around it: metering, spend policy, and settlement reporting. Every company deploying agents will need to answer "what did our agents spend, on what, and who authorised it" — and almost nobody has built that yet.

Arc's own builder call names this frontier directly: autonomous businesses — zero-person companies that earn, spend and settle entirely onchain.
